## 1. What is a VIEW?

Think of a **VIEW as a window**.

A **TABLE** contains the actual data.

A **VIEW** shows selected data from the table.

```text
TABLE
  ↓
Actual data
  ↓
VIEW
  ↓
Shows selected data
```

### Simple Definition

> **VIEW = A virtual table created from a SQL query.**

A normal view does not usually store another copy of the data. It stores the query used to get the data.

### 🛠️ Practical Example

Create a table:

```sql
CREATE TABLE EMP_INFO (
    ID INT PRIMARY KEY,
    NAME VARCHAR(50),
    DEPT VARCHAR(30),
    SALARY INT
);
```

Insert data:

```sql
INSERT INTO EMP_INFO VALUES
(101, 'Ravi', 'HR', 45000),
(102, 'Anita', 'IT', 70000),
(103, 'Suman', 'Finance', 85000),
(104, 'John', 'IT', 90000),
(105, 'Priya', 'HR', 40000);
```

Create a simple view:

```sql
CREATE VIEW employee_view AS
SELECT ID, NAME, DEPT
FROM EMP_INFO;
```

Now:

```sql
SELECT * FROM employee_view;
```

The view shows selected data from `EMP_INFO`.

---

## 2. Simple VIEW Example

Suppose we want **only employees whose salary is above 60000**.

Create a VIEW:

```sql
CREATE VIEW high_salary_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE SALARY > 60000;
```

Now:

```sql
SELECT * FROM high_salary_employees;
```

Output:

```text
ID    NAME    SALARY
--------------------
102   Anita   70000
103   Suman   85000
104   John    90000
```

Think like this:

```text
EMP_INFO
   ↓
WHERE SALARY > 60000
   ↓
VIEW
   ↓
Anita
Suman
John
```

### 🧠 Remember

> **VIEW shows the result of a SELECT query.**

## 3. VIEW from One Table

A view can come from just **one table**.

### 🛠️ Practical Example

Create a view for only IT employees:

```sql
CREATE VIEW it_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE DEPT = 'IT';
```

Now:

```sql
SELECT * FROM it_employees;
```

Output:

```text
ID    NAME    SALARY
--------------------
102   Anita   70000
104   John    90000
```

Here:

```text
EMP_INFO
   ↓
WHERE DEPT = 'IT'
   ↓
it_employees VIEW
```

### 🧠 Remember

> **One table → VIEW is possible.**

---

## 4. VIEW from Multiple Tables

A view can also combine information from **multiple tables**.

### 🛠️ Practical Example

Create a department table:

```sql
CREATE TABLE DEPARTMENT (
    DEPT_ID INT PRIMARY KEY,
    DEPT_NAME VARCHAR(30),
    LOCATION VARCHAR(30)
);
```

Insert data:

```sql
INSERT INTO DEPARTMENT VALUES
(1, 'HR', 'Hyderabad'),
(2, 'IT', 'Bangalore'),
(3, 'Finance', 'Chennai');
```

Create a view using both tables:

```sql
CREATE VIEW employee_details AS
SELECT E.ID, E.NAME, E.DEPT, D.LOCATION
FROM EMP_INFO E
JOIN DEPARTMENT D
ON E.DEPT = D.DEPT_NAME;
```

Now:

```sql
SELECT * FROM employee_details;
```

Output:

```text
ID    NAME    DEPT      LOCATION
---------------------------------
101   Ravi    HR        Hyderabad
102   Anita   IT        Bangalore
103   Suman   Finance   Chennai
104   John    IT        Bangalore
105   Priya   HR        Hyderabad
```

Think:

```text
EMP_INFO        DEPARTMENT
    ↓                ↓
 Employee data    Location data
       \            /
        \          /
           JOIN
            ↓
           VIEW
```

### 🧠 Remember

> **VIEW can combine data from multiple tables.**

## 5. VIEW Can Hide Columns 🔒

Suppose the table has:

```text
ID
NAME
DEPT
SALARY
```

But you don't want users to see `SALARY`.

### 🛠️ Practical Example

Create a view without `SALARY`:

```sql
CREATE VIEW employee_public AS
SELECT ID, NAME, DEPT
FROM EMP_INFO;
```

Now:

```sql
SELECT * FROM employee_public;
```

Output:

```text
ID    NAME    DEPT
-------------------
101   Ravi    HR
102   Anita   IT
103   Suman   Finance
104   John    IT
105   Priya   HR
```

`SALARY` is not shown through this view.

Think:

```text
TABLE
ID | NAME | DEPT | SALARY
             ↓
           VIEW
             ↓
       ID | NAME | DEPT
```

### 🧠 Remember

> **VIEW can show only the columns we want.**

> **VIEW can show only the rows we want.**

# 7. TABLE Changes → VIEW Changes 🔄

This is very important.

A normal view gets its result from the underlying table.

### 🛠️ Practical Example

Create the view:

```sql
CREATE VIEW high_salary_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE SALARY > 60000;
```

Initially:

```text
Anita   70000  ✅
Suman   85000  ✅
John    90000  ✅
```

Now change Anita's salary in the **TABLE**:

```sql
UPDATE EMP_INFO
SET SALARY = 50000
WHERE ID = 102;
```

Check the table:

```sql
SELECT * FROM EMP_INFO
WHERE ID = 102;
```

Output:

```text
102   Anita   IT   50000
```

Now check the VIEW:

```sql
SELECT * FROM high_salary_employees;
```

Output:

```text
Suman   85000
John    90000
```

Anita disappeared.

Why?

```text
Anita's salary = 50000

50000 > 60000
     ↓
   FALSE
     ↓
Not shown in VIEW
```

### 🧠 Remember

> **TABLE changes → VIEW result can change.**

---

# 8. VIEW Changes → TABLE Changes 🔄

This is different.

**Some views are updatable.**

That means we can perform changes through the view, and those changes can affect the underlying table.

### 🛠️ Practical Example

Create a simple view:

```sql
CREATE VIEW employee_salary AS
SELECT ID, NAME, SALARY
FROM EMP_INFO;
```

Now update through the view:

```sql
UPDATE employee_salary
SET SALARY = 75000
WHERE ID = 102;
```

Check the table:

```sql
SELECT * FROM EMP_INFO
WHERE ID = 102;
```

Output:

```text
ID    NAME    DEPT    SALARY
----------------------------
102   Anita   IT      75000
```

The table changed.

Think:

```text
VIEW
  ↓
UPDATE
  ↓
TABLE
  ↓
SALARY becomes 75000
```

### 🧠 Remember

> **An updatable VIEW can change the underlying TABLE.**

⚠️ **Not every view is updatable.**

# 10. VIEW for Security 🔒

A table may contain sensitive information.

For example:

```text
EMP_INFO

ID
NAME
DEPT
SALARY
```

Suppose normal users should not see `SALARY`.

### 🛠️ Practical Example

Create a public view:

```sql
CREATE VIEW employee_public AS
SELECT ID, NAME, DEPT
FROM EMP_INFO;
```

Now users query:

```sql
SELECT * FROM employee_public;
```

They see:

```text
ID    NAME    DEPT
-------------------
101   Ravi    HR
102   Anita   IT
103   Suman   Finance
```

They do not see:

```text
SALARY
```

Think:

```text
TABLE
ID | NAME | DEPT | SALARY
             ↓
           VIEW
             ↓
       ID | NAME | DEPT
```

### 🧠 Remember

> **VIEW can help hide sensitive columns and rows.**

⚠️ Proper database permissions should also be used for complete security.

# 12. VIEW Makes Complex Queries Easy

Suppose this JOIN is complicated:

```sql
SELECT E.ID, E.NAME, E.DEPT, D.LOCATION
FROM EMP_INFO E
JOIN DEPARTMENT D
ON E.DEPT = D.DEPT_NAME;
```

If we need this query many times, create a view.

### 🛠️ Practical Example

Create:

```sql
CREATE VIEW employee_details AS
SELECT E.ID, E.NAME, E.DEPT, D.LOCATION
FROM EMP_INFO E
JOIN DEPARTMENT D
ON E.DEPT = D.DEPT_NAME;
```

Instead of writing the JOIN again:

```sql
SELECT * FROM employee_details;
```

Output:

```text
ID    NAME    DEPT      LOCATION
---------------------------------
101   Ravi    HR        Hyderabad
102   Anita   IT        Bangalore
103   Suman   Finance   Chennai
```

### 🧠 Remember

> **VIEW can make complicated queries easier to use.**

# 13. Not Every VIEW Can Be Updated ❌

Simple views may be updatable.

But views using things like:

```text
GROUP BY
SUM()
AVG()
DISTINCT
```

may not be directly updatable.

### 🛠️ Practical Example

Create a view that calculates average salary:

```sql
CREATE VIEW department_salary AS
SELECT DEPT, AVG(SALARY) AS AVG_SALARY
FROM EMP_INFO
GROUP BY DEPT;
```

Now:

```sql
SELECT * FROM department_salary;
```

Possible output:

```text
DEPT       AVG_SALARY
---------------------
HR         42500
IT         82500
Finance    85000
```

`AVG_SALARY` is a **calculated value**.

Trying to change it directly:

```sql
UPDATE department_salary
SET AVG_SALARY = 90000
WHERE DEPT = 'IT';
```

Generally, this cannot be performed because `AVG_SALARY` is calculated from multiple rows.

### 🧠 Remember

> **Simple VIEW → may be updatable.**

> **Complex VIEW → may not be updatable.**

# 14. Does VIEW Make Queries Faster? ⚡

**Not automatically.**

A normal view mainly gives:

```text
✅ Easy queries
✅ Security
✅ Abstraction
✅ Reusable query
```

It does **not automatically make a query faster**.

### 🛠️ Practical Example

Create:

```sql
CREATE VIEW employee_details AS
SELECT E.ID, E.NAME, E.DEPT, D.LOCATION
FROM EMP_INFO E
JOIN DEPARTMENT D
ON E.DEPT = D.DEPT_NAME;
```

Now:

```sql
SELECT * FROM employee_details;
```

The view makes the query easier to write, but the view itself does not automatically make the query faster.

### 🧠 Remember

> **VIEW = convenience, security, and abstraction.**

> **VIEW ≠ automatically faster.**

# 15. Delete a VIEW 🗑️

To remove a view:

```sql
DROP VIEW high_salary_employees;
```

### 🛠️ Practical Example

Before:

```text
EMP_INFO
   ↓
high_salary_employees VIEW
```

Run:

```sql
DROP VIEW high_salary_employees;
```

After:

```text
EMP_INFO
```

The **VIEW is deleted**.

The **TABLE is still there**.

Check:

```sql
SELECT * FROM EMP_INFO;
```

The table data is still available.

### 🧠 Remember

> **DROP VIEW → deletes the VIEW, NOT the TABLE.**
