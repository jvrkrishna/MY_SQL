# SQL VIEW

## 1. What is a View?

A **View** is a **virtual table** created from one or more existing tables using a SQL query.

A view normally does not store a separate copy of the actual data. Instead, it stores the **SQL query definition** used to retrieve the data.

### Simple Definition

> A View is a virtual table based on the result of a `SELECT` query.

### Example

First, create a table:

```sql
CREATE TABLE EMP_INFO (
    ID INT PRIMARY KEY,
    NAME VARCHAR(50),
    DEPT VARCHAR(30),
    SALARY INT
);
```

Insert some records:

```sql
INSERT INTO EMP_INFO (ID, NAME, DEPT, SALARY) VALUES
(101, 'Ravi', 'HR', 45000),
(102, 'Anita', 'IT', 70000),
(103, 'Suman', 'Finance', 85000),
(104, 'John', 'IT', 90000),
(105, 'Priya', 'HR', 40000);
```

Now create a view:

```sql
CREATE VIEW high_salary_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE SALARY > 60000;
```

Here:

```text
EMP_INFO
   ↓
SELECT ID, NAME, SALARY
WHERE SALARY > 60000
   ↓
high_salary_employees (VIEW)
```

The view behaves like a virtual table:

```sql
SELECT * FROM high_salary_employees;
```

Output:

```text
ID     NAME      SALARY
-----  --------  ------
102    Anita     70000
103    Suman     85000
104    John      90000
```

---

# 2. A View Can Be Created from One Table

A view can be created using a single table.

### Example

```sql
CREATE VIEW it_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE DEPT = 'IT';
```

Now:

```sql
SELECT * FROM it_employees;
```

Output:

```text
ID     NAME      SALARY
-----  --------  ------
102    Anita     70000
104    John      90000
```

Here, the view is created from only one table:

```text
EMP_INFO
   ↓
WHERE DEPT = 'IT'
   ↓
it_employees
```

---

# 3. A View Can Be Created from Multiple Tables

A view can also be created using multiple tables, usually with joins.

### Example

Create a department table:

```sql
CREATE TABLE DEPARTMENT (
    DEPT_ID INT PRIMARY KEY,
    DEPT_NAME VARCHAR(30),
    LOCATION VARCHAR(30)
);
```

Insert data:

```sql
INSERT INTO DEPARTMENT VALUES
(1, 'HR', 'Hyderabad'),
(2, 'IT', 'Bangalore'),
(3, 'Finance', 'Chennai');
```

Suppose we want employee information along with the department location.

Create a view:

```sql
CREATE VIEW employee_details AS
SELECT E.ID, E.NAME, E.DEPT, D.LOCATION
FROM EMP_INFO E
JOIN DEPARTMENT D
ON E.DEPT = D.DEPT_NAME;
```

Now:

```sql
SELECT * FROM employee_details;
```

Possible output:

```text
ID     NAME      DEPT       LOCATION
-----  --------  ---------  ---------
101    Ravi      HR         Hyderabad
102    Anita     IT         Bangalore
103    Suman     Finance    Chennai
104    John      IT         Bangalore
105    Priya     HR         Hyderabad
```

So a view can combine data from multiple tables.

---

# 4. A View Can Contain Selected Columns

A view does not have to display every column from the base table.

### Example

Our `EMP_INFO` table contains:

```text
ID
NAME
DEPT
SALARY
```

Suppose we don't want users to see the salary.

Create:

```sql
CREATE VIEW employee_public AS
SELECT ID, NAME, DEPT
FROM EMP_INFO;
```

Query:

```sql
SELECT * FROM employee_public;
```

Output:

```text
ID     NAME      DEPT
-----  --------  ---------
101    Ravi      HR
102    Anita     IT
103    Suman     Finance
104    John      IT
105    Priya     HR
```

The `SALARY` column is not exposed through this view.

### Use

This is useful when we want to give users access to only the required columns.

---

# 5. A View Can Contain Selected Rows

A view can display only the rows that satisfy a condition.

### Example

Create a view for employees whose salary is greater than `60000`:

```sql
CREATE VIEW high_salary_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE SALARY > 60000;
```

Query:

```sql
SELECT * FROM high_salary_employees;
```

Output:

```text
ID     NAME      SALARY
-----  --------  ------
102    Anita     70000
103    Suman     85000
104    John      90000
```

Employees with salaries of `60000` or less are not shown in this view.

---

# 6. Changes in the Base Table Are Reflected in the View

A normal view is based on the underlying table data.

Therefore, when the base table changes, the result of the view can also change when we query it.

### Example

Initially:

```text
ID     NAME      SALARY
-----  --------  ------
102    Anita     70000
103    Suman     85000
104    John      90000
```

Our view condition is:

```sql
WHERE SALARY > 60000
```

Now update Anita's salary:

```sql
UPDATE EMP_INFO
SET SALARY = 50000
WHERE ID = 102;
```

Query the view again:

```sql
SELECT * FROM high_salary_employees;
```

Output:

```text
ID     NAME      SALARY
-----  --------  ------
103    Suman     85000
104    John      90000
```

Anita disappeared from the view because her salary is now `50000`.

> Changes made to the underlying table can be reflected in the view when the view is queried, depending on the view's definition.

---

# 7. Changes Made Through a View Can Reflect in the Base Table

Some views are **updatable**.

If a view is updatable, an `UPDATE`, `INSERT`, or `DELETE` performed through the view can modify the underlying table.

### Example

Create this simple view:

```sql
CREATE VIEW employee_salary AS
SELECT ID, NAME, SALARY
FROM EMP_INFO;
```

Now update Anita's salary through the view:

```sql
UPDATE employee_salary
SET SALARY = 75000
WHERE ID = 102;
```

Check the base table:

```sql
SELECT * FROM EMP_INFO
WHERE ID = 102;
```

Output:

```text
ID     NAME      DEPT    SALARY
-----  --------  ------  ------
102    Anita     IT      75000
```

The update made through the view changed the underlying table.

### Important

Do not say:

> Changes made in view always reflect in table.

Correct statement:

> Changes made through an **updatable view** can modify the underlying base table.

Not every view is updatable.

# 8. Data Security Using Views

One of the important advantages of a view is **data security**.

A table may contain sensitive information that should not be shown to every user.

### Example

Our table contains:

```text
ID
NAME
DEPT
SALARY
```

Suppose normal employees should not see salary information.

Create:

```sql
CREATE VIEW employee_public AS
SELECT ID, NAME, DEPT
FROM EMP_INFO;
```

Now give users access to the view instead of the original table.

```sql
SELECT * FROM employee_public;
```

Output:

```text
ID     NAME      DEPT
-----  --------  ---------
101    Ravi      HR
102    Anita     IT
103    Suman     Finance
104    John      IT
105    Priya     HR
```

The salary column is hidden.

### Advantage

> Views can restrict the rows and columns exposed to users, helping with data security.

Note: Proper database permissions should also be used for complete security.

### Example


For HR:

```sql
CREATE VIEW hr_employees AS
```

Output:

# 10. View Reduces Query Complexity

A view can hide a complicated SQL query.

Suppose we frequently need employee information along with department location.

Instead of writing the join every time:

```sql
SELECT E.ID, E.NAME, E.DEPT, D.LOCATION
FROM EMP_INFO E
JOIN DEPARTMENT D
ON E.DEPT = D.DEPT_NAME;
```

We can create a view:

```sql
CREATE VIEW employee_details AS
SELECT E.ID, E.NAME, E.DEPT, D.LOCATION
FROM EMP_INFO E
JOIN DEPARTMENT D
ON E.DEPT = D.DEPT_NAME;
```

Now users can simply write:

```sql
SELECT * FROM employee_details;
```

### Advantage

> A view can simplify frequently used complex queries.

---

# 11. Storage Space Used by a Normal View

A normal view generally stores the **query definition**, not a separate copy of the result data.

### Example

```sql
CREATE VIEW high_salary_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE SALARY > 60000;
```

The database does not normally create another physical copy of:

```text
Anita
Suman
John
```

Instead, the view definition is stored and the database obtains the current result from the underlying table when the view is queried.

### Advantage

> A normal view generally requires little additional storage compared with storing a separate copy of the data.

---

# 12. View Is Not Always Updatable

Not every view can be modified directly.

Simple views are more likely to be updatable, while complex views may not be.

### Example of a Complex View

Suppose we create:

```sql
CREATE VIEW department_salary AS
SELECT DEPT, AVG(SALARY) AS AVG_SALARY
FROM EMP_INFO
GROUP BY DEPT;
```

Query:

```sql
SELECT * FROM department_salary;
```

Possible output:

```text
DEPT       AVG_SALARY
---------  ----------
HR         42500
IT         82500
Finance    85000
```

Now consider:

```sql
UPDATE department_salary
SET AVG_SALARY = 90000
WHERE DEPT = 'IT';
```

This generally cannot be performed because `AVG_SALARY` is a calculated aggregate value, not a direct column stored in a single base-table row.

### Important

Views containing features such as:

* `GROUP BY`
* Aggregate functions
* `DISTINCT`
* Certain joins
* Certain calculated expressions

may not be directly updatable, depending on the database system.

---

# 13. Indexing a View

The statement:

> Views cannot be indexed.

is **not universally correct**.

For a normal view, the view usually does not have its own physical storage, so it generally does not have its own ordinary indexes.

### Example

```sql
CREATE VIEW high_salary_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE SALARY > 60000;
```

This normal view generally does not have a separate index structure like a physical table.

However, some database systems support special features such as **indexed views** or **materialized views**.

### Correct Statement

> A normal view generally does not have its own indexes, but some database systems support indexed or materialized views.

---

# 14. View Performance

A view does not automatically make a query faster.

### Example

Suppose:

```sql
CREATE VIEW employee_details AS
SELECT E.ID, E.NAME, E.DEPT, D.LOCATION
FROM EMP_INFO E
JOIN DEPARTMENT D
ON E.DEPT = D.DEPT_NAME;
```

When we execute:

```sql
SELECT * FROM employee_details;
```

> A view mainly provides abstraction, security, and convenience. It does not automatically improve query performance.

---

# 15. DROP VIEW

We can remove a view using:

```sql
DROP VIEW high_salary_employees;
```

This removes the **view**, not the underlying table.

### Example

Before:

```text
EMP_INFO
   ↓
high_salary_employees (VIEW)
```

Execute:

```sql
DROP VIEW high_salary_employees;
```

After:

```text
EMP_INFO
```

The `EMP_INFO` table still exists.

We can verify:

```sql
SELECT * FROM EMP_INFO;
```

The table data remains.

# Complete Practical Example

Here is the complete example in the correct execution order.

## Step 1 — Create Table

```sql
CREATE TABLE EMP_INFO (
    ID INT PRIMARY KEY,
    NAME VARCHAR(50),
    DEPT VARCHAR(30),
    SALARY INT
);
```

## Step 2 — Insert Data

```sql
INSERT INTO EMP_INFO (ID, NAME, DEPT, SALARY) VALUES
(101, 'Ravi', 'HR', 45000),
(102, 'Anita', 'IT', 70000),
(103, 'Suman', 'Finance', 85000),
(104, 'John', 'IT', 90000),
(105, 'Priya', 'HR', 40000);
```

## Step 3 — Create View

```sql
CREATE VIEW high_salary_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE SALARY > 60000;
```

## Step 4 — Query View

```sql
SELECT * FROM high_salary_employees;
```

Output:

```text
ID     NAME      SALARY
-----  --------  ------
102    Anita     70000
103    Suman     85000
104    John      90000
```

## Step 5 — Update Through View

```sql
UPDATE high_salary_employees
SET SALARY = 75000
WHERE ID = 102;
```

Check the table:

```sql
SELECT * FROM EMP_INFO
WHERE ID = 102;
```

Output:

```text
ID     NAME      DEPT    SALARY
-----  --------  ------  ------
102    Anita     IT      75000
```

## Step 6 — Update Base Table

Now change Anita's salary so that she no longer satisfies the view condition:

```sql
UPDATE EMP_INFO
SET SALARY = 50000
WHERE ID = 102;
```

Query the view:

```sql
SELECT * FROM high_salary_employees;
```

Output:

```text
ID     NAME      SALARY
-----  --------  ------
103    Suman     85000
104    John      90000
```

Anita is no longer displayed because:

```text
50000 > 60000
FALSE
```

## Step 7 — Drop the View

```sql
DROP VIEW high_salary_employees;
```

The view is deleted, but `EMP_INFO` remains.
