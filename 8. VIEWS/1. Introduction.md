# SQL VIEW — Simple Notes

## 1. What is a VIEW?

Think of a **VIEW as a window**.

A **TABLE** contains the actual data.

A **VIEW** shows selected data from the table.

```text
TABLE
  ↓
Actual data
  ↓
VIEW
  ↓
Shows selected data
```

### Simple Definition

> **VIEW = A virtual table created from a SQL query.**

A normal view does not usually store another copy of the data. It stores the query used to get the data.

---

## 2. Simple Example

We have a table:

```text
EMP_INFO

ID    NAME    DEPT      SALARY
--------------------------------
101   Ravi    HR        45000
102   Anita   IT        70000
103   Suman   Finance   85000
104   John    IT        90000
105   Priya   HR        40000
```

Suppose we want **only employees whose salary is above 60000**.

Create a VIEW:

```sql
CREATE VIEW high_salary_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE SALARY > 60000;
```

Now:

```sql
SELECT * FROM high_salary_employees;
```

We see:

```text
ID    NAME    SALARY
--------------------
102   Anita   70000
103   Suman   85000
104   John    90000
```

Think like this:

```text
EMP_INFO
   ↓
WHERE SALARY > 60000
   ↓
VIEW
   ↓
Anita
Suman
John
```

---

## 3. VIEW from One Table

A view can come from just **one table**.

```sql
CREATE VIEW it_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE DEPT = 'IT';
```

Now:

```sql
SELECT * FROM it_employees;
```

Result:

```text
Anita   IT   70000
John    IT   90000
```

So:

> **One table → VIEW is possible.**

---

## 4. VIEW from Multiple Tables

A view can also combine information from **multiple tables**.

```text
EMP_INFO              DEPARTMENT
   ↓                       ↓
Employee data          Department data
          \             /
           \           /
             JOIN
               ↓
              VIEW
```

Example:

```sql
CREATE VIEW employee_details AS
SELECT E.ID, E.NAME, E.DEPT, D.LOCATION
FROM EMP_INFO E
JOIN DEPARTMENT D
ON E.DEPT = D.DEPT_NAME;
```

Now the view can show:

```text
ID    NAME    DEPT      LOCATION
---------------------------------
101   Ravi    HR        Hyderabad
102   Anita   IT        Bangalore
```

So:

> **VIEW can combine data from multiple tables.**

---

## 5. VIEW Can Hide Columns 🔒

Suppose the table has:

```text
ID
NAME
DEPT
SALARY
```

But you don't want users to see `SALARY`.

Create:

```sql
CREATE VIEW employee_public AS
SELECT ID, NAME, DEPT
FROM EMP_INFO;
```

Now the user sees:

```text
ID    NAME    DEPT
-------------------
101   Ravi    HR
102   Anita   IT
103   Suman   Finance
```

They don't see:

```text
SALARY
```

So:

> **VIEW can show only the columns we want.**

---

## 6. VIEW Can Hide Rows

Suppose we only want employees with salary greater than `60000`.

```sql
CREATE VIEW high_salary_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE SALARY > 60000;
```

The view shows:

```text
Anita   70000
Suman   85000
John    90000
```

It doesn't show:

```text
Ravi    45000
Priya   40000
```

So:

> **VIEW can show only the rows we want.**

---

# 7. TABLE Changes → VIEW Changes 🔄

This is very important.

Suppose the view says:

```sql
WHERE SALARY > 60000;
```

Initially:

```text
Anita   70000  ✅
Suman   85000  ✅
John    90000  ✅
```

Now change Anita's salary in the **table**:

```sql
UPDATE EMP_INFO
SET SALARY = 50000
WHERE ID = 102;
```

Now check the view:

```sql
SELECT * FROM high_salary_employees;
```

Anita is gone!

```text
Suman   85000
John    90000
```

Why?

```text
Anita's salary = 50000

50000 > 60000
     ↓
   FALSE
     ↓
Not shown in VIEW
```

### Remember:

> **TABLE changes → VIEW result can change.**

---

# 8. VIEW Changes → TABLE Changes 🔄

This is a little different.

**Some views are updatable.**

For example:

```sql
CREATE VIEW employee_salary AS
SELECT ID, NAME, SALARY
FROM EMP_INFO;
```

Now:

```sql
UPDATE employee_salary
SET SALARY = 75000
WHERE ID = 102;
```

If this is an **updatable view**, the actual table also changes.

Think:

```text
VIEW
  ↓
UPDATE
  ↓
TABLE
  ↓
SALARY becomes 75000
```

So:

> **An updatable VIEW can change the underlying TABLE.**

⚠️ But **not every view is updatable**.

# 10. VIEW for Security 🔒

Suppose:

```text
EMP_INFO

ID
NAME
DEPT
SALARY
```

You don't want normal users to see salary.

Create:

```sql
CREATE VIEW employee_public AS
SELECT ID, NAME, DEPT
FROM EMP_INFO;
```

Now give users access to the **VIEW**, rather than the original table.

```text
TABLE
ID | NAME | DEPT | SALARY
             ↓
           VIEW
             ↓
       ID | NAME | DEPT
```

So:

> **VIEW can help hide sensitive columns and rows.**

---

# 11. Different VIEWs for Different Users

For IT:

```sql
CREATE VIEW it_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE DEPT = 'IT';
```

For HR:

```sql
CREATE VIEW hr_employees AS
SELECT ID, NAME, SALARY
FROM EMP_INFO
WHERE DEPT = 'HR';
```

Same table:

```text
             EMP_INFO
            /        \
           /          \
      IT VIEW       HR VIEW
         ↓              ↓
     IT employees    HR employees
```

So:

> **Different users can see different views of the same table.**

---

# 12. VIEW Makes Complex Queries Easy

Suppose this JOIN is complicated:

```sql
SELECT E.ID, E.NAME, E.DEPT, D.LOCATION
FROM EMP_INFO E
JOIN DEPARTMENT D
ON E.DEPT = D.DEPT_NAME;
```

Instead of writing it every time, create a view:

```sql
CREATE VIEW employee_details AS
SELECT E.ID, E.NAME, E.DEPT, D.LOCATION
FROM EMP_INFO E
JOIN DEPARTMENT D
ON E.DEPT = D.DEPT_NAME;
```

Then simply:

```sql
SELECT * FROM employee_details;
```

So:

> **VIEW can make complicated queries easier to use.**

---

# 13. Not Every VIEW Can Be Updated ❌

Simple view:

```sql
CREATE VIEW employee_salary AS
SELECT ID, NAME, SALARY
FROM EMP_INFO;
```

May be updatable.

But a view using:

```text
GROUP BY
SUM()
AVG()
DISTINCT
```

may not be directly updatable.

Example:

```sql
CREATE VIEW department_salary AS
SELECT DEPT, AVG(SALARY)
FROM EMP_INFO
GROUP BY DEPT;
```

Here `AVG(SALARY)` is a **calculated value**.

So this generally cannot be directly updated:

```sql
UPDATE department_salary
SET AVG(SALARY) = 90000;
```

### Remember:

> **Simple VIEW → may be updatable.**

> **Complex VIEW → may not be updatable.**

---

# 14. Does VIEW Make Queries Faster? ⚡

**Not automatically.**

A normal view mainly gives:

```text
✅ Easy queries
✅ Security
✅ Abstraction
✅ Reusable query
```

It does **not automatically mean faster queries**.

---

# 15. Delete a VIEW 🗑️

To remove a view:

```sql
DROP VIEW high_salary_employees;
```

⚠️ This deletes **only the VIEW**.

It does **NOT delete the table**.

```text
Before:

EMP_INFO
   ↓
VIEW


DROP VIEW


After:

EMP_INFO
```

The table and its data are still there.

---

# 🧠 FINAL MEMORY TRICK

Think of a **TABLE as a house 🏠** and a **VIEW as a window 🪟**.

```text
TABLE = House
       ↓
   Actual data


VIEW = Window
       ↓
Shows selected data
```

### Remember these 6 points:

1. **TABLE = actual data**
2. **VIEW = window to the data**
3. **Table changes → View result can change**
4. **Updatable View → can change Table**
5. **View can hide rows/columns**
6. **DROP VIEW → deletes view, NOT table**

### One-line definition

> 🧠 **VIEW = A virtual table that shows selected data from one or more tables.**
