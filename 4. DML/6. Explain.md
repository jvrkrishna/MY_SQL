# EXPLAIN in MySQL

`EXPLAIN` is a MySQL statement used to understand **how MySQL executes a SQL query**.

It is mainly used for **query analysis and optimization**.

EXPLAIN helps us understand:

- Which indexes MySQL can use
- Which index MySQL actually uses
- How tables are accessed
- The order in which tables are processed
- The estimated number of rows MySQL needs to examine
- Whether MySQL uses a full table scan
- Whether temporary tables or filesort operations are used

---

# 1. Why Do We Use EXPLAIN?

Suppose we have this query:

    SELECT NAME
    FROM EMP_INFO
    WHERE SALARY = 10000;

The query may work correctly, but we may want to know:

- Is MySQL using an index?
- Is MySQL checking every row?
- How many rows does MySQL expect to examine?
- Can the query be optimized?

We can use:

    EXPLAIN SELECT NAME
    FROM EMP_INFO
    WHERE SALARY = 10000;

EXPLAIN does not execute the query in the same way as a normal SELECT. Instead, it shows the **execution plan** that MySQL expects to use.

---

# 2. Basic Syntax

### Syntax

    EXPLAIN SELECT statement;

### Example

    EXPLAIN SELECT *
    FROM EMP_INFO;

Another example:

    EXPLAIN SELECT NAME
    FROM EMP_INFO
    WHERE SALARY = 10000;

---

# 3. Create a Table

Let's create a table to understand EXPLAIN.

    CREATE TABLE EMP_INFO (
        ID INT PRIMARY KEY,
        NAME VARCHAR(50),
        SALARY FLOAT,
        DEPARTMENT VARCHAR(50)
    );

# 5. View the Table Structure

We can use `DESC` to see the structure of the table.

    DESC EMP_INFO;

Output:

    +------------+-------------+------+-----+---------+-------+
    | Field      | Type        | Null | Key | Default | Extra |
    +------------+-------------+------+-----+---------+-------+
    | ID         | int         | NO   | PRI | NULL    |       |
    | NAME       | varchar(50) | YES  |     | NULL    |       |
    | SALARY     | float       | YES  |     | NULL    |       |
    | DEPARTMENT | varchar(50) | YES  |     | NULL    |       |
    +------------+-------------+------+-----+---------+-------+

### Explanation

`Field`

The name of the column.

`Type`

The data type of the column.

`Null`

Shows whether the column can contain `NULL`.

`Key`

Shows whether the column is indexed or has a key.

For example:

    PRI

means the column is part of the `PRIMARY KEY`.

`Default`

Shows the default value of the column.

`Extra`

Shows additional information about the column.

---

# 6. Check Indexes

We can use `SHOW INDEX` to see the indexes defined on a table.

### Syntax

    SHOW INDEXES FROM table_name;

### Example

    SHOW INDEXES FROM EMP_INFO;

Since `ID` is the primary key, MySQL automatically creates an index for the primary key.

The output contains information such as:

- `Key_name`
- `Column_name`
- `Non_unique`
- `Cardinality`

---

# 7. Important Index Terms

## Key_name

The name of the index.

For example:

    PRIMARY

or:

    idx_salary

---

## Column_name

The column on which the index is created.

Example:

    SALARY

---

## Non_unique

Indicates whether duplicate values are allowed in the index.

    0 -> Unique

    1 -> Duplicate values are allowed

A primary key index is unique, so `Non_unique` is normally `0`.

---

## Cardinality

Cardinality is an estimate of the number of unique values in an index.

It helps MySQL's optimizer decide whether an index is useful.

---

# 8. EXPLAIN Without an Index

Consider the following query:

    SELECT NAME
    FROM EMP_INFO
    WHERE SALARY = 10000;

Currently, `SALARY` does not have an index.

We can check the execution plan:

    EXPLAIN
    SELECT NAME
    FROM EMP_INFO
    WHERE SALARY = 10000;

A sample output may look like:

    +----+-------------+----------+------+---------------+------+---------+------+------+-------------+
    | id | select_type | table    | type | possible_keys | key  | key_len | ref  | rows | Extra       |
    +----+-------------+----------+------+---------------+------+---------+------+------+-------------+
    | 1  | SIMPLE      | EMP_INFO | ALL  | NULL          | NULL | NULL    | NULL | 5    | Using where |
    +----+-------------+----------+------+---------------+------+---------+------+------+-------------+

The exact output can vary depending on the MySQL version, table statistics, indexes, and optimizer decisions.

---

# 9. Understanding the EXPLAIN Output

The important columns in the output are:

- `id`
- `select_type`
- `table`
- `type`
- `possible_keys`
- `key`
- `key_len`
- `ref`
- `rows`
- `Extra`

---

# 10. id

`id` identifies the SELECT operation in the execution plan.

For a simple query, it is usually:

    1

Example:

    id = 1

For more complicated queries containing subqueries or multiple SELECT operations, multiple IDs may appear.

---

# 11. select_type

`select_type` tells us what type of SELECT operation MySQL is processing.

For a simple query:

    SIMPLE

means the query does not contain a subquery or UNION.

Example:

    SELECT *
    FROM EMP_INFO;

EXPLAIN may show:

    SIMPLE

---

# 12. table

The `table` column shows the table MySQL is accessing.

Example:

    EMP_INFO

This means MySQL is reading data from the `EMP_INFO` table.

---

# 13. type

`type` describes how MySQL accesses the table.

Some commonly seen values are:

    ALL
    index
    range
    ref
    eq_ref
    const

The access type is very important when analyzing query performance.

---

## type = ALL

`ALL` means MySQL is performing a **full table scan**.

Example:

    SELECT NAME
    FROM EMP_INFO
    WHERE SALARY = 10000;

If there is no suitable index on `SALARY`, MySQL may check every row.

EXPLAIN may show:

    type = ALL

For a small table this may be perfectly acceptable.

For a very large table, a full table scan can be expensive.

---

## type = ref

`ref` indicates that MySQL is using a non-unique index to find matching rows.

For example, if `SALARY` has an index:

    CREATE INDEX idx_salary
    ON EMP_INFO(SALARY);

Then:

    EXPLAIN
    SELECT NAME
    FROM EMP_INFO
    WHERE SALARY = 10000;

may show:

    type = ref

This indicates an index-based lookup.

---

## type = range

`range` is used when MySQL searches a range of index values.

Example:

    SELECT *
    FROM EMP_INFO
    WHERE SALARY > 10000;

EXPLAIN may show:

    type = range

---

## type = const

`const` can occur when MySQL can identify at most one matching row using a primary key or unique index.

Example:

    SELECT *
    FROM EMP_INFO
    WHERE ID = 1;

Since `ID` is the primary key, MySQL can directly locate the row.

---

# 14. possible_keys

`possible_keys` shows the indexes that MySQL considers potentially useful for the query.

Example:

    possible_keys = idx_salary

This means MySQL sees `idx_salary` as a possible index for the query.

Important:

`possible_keys` does not mean that MySQL actually uses the index.

To see the index actually selected, look at the `key` column.

---

# 15. key

`key` shows the index MySQL actually chooses to use.

If we see:

    key = idx_salary

MySQL is using the `idx_salary` index.

If we see:

    key = NULL

MySQL is not using an index for that table access.

---

# 16. key_len

`key_len` shows the length of the portion of the index that MySQL uses.

The value depends on the data type and other properties of the indexed column.

It is mainly useful when analyzing indexes involving multiple columns.

---

# 17. ref

`ref` shows which value or column is compared with the index.

For example, an EXPLAIN result might show:

    ref = const

This means the indexed column is being compared with a constant value.

Example:

    WHERE SALARY = 10000

Here, `10000` is a constant.

---

# 18. rows

`rows` is an estimate of how many rows MySQL expects to examine.

For example:

    rows = 5

means MySQL estimates that approximately 5 rows may need to be examined.

If an index reduces this to:

    rows = 2

it can indicate that MySQL expects to examine fewer rows.

Important:

`rows` is an estimate, not necessarily the exact number of rows actually processed.

---

# 19. Extra

`Extra` provides additional information about how MySQL executes the query.

For example:

    Using where

means MySQL uses a `WHERE` condition to filter rows.

Other possible values include:

    Using index
    Using temporary
    Using filesort
    Using index condition

---

# 20. Using where

Example:

    Extra = Using where

This means MySQL uses the `WHERE` condition to filter the rows.

Example:

    SELECT NAME
    FROM EMP_INFO
    WHERE SALARY = 10000;

---

# 21. Using index

`Using index` can indicate that MySQL can satisfy the query using only information stored in the index.

This is sometimes called a **covering index** situation.

For example, if an index contains all the columns needed by the query, MySQL may not need to read the table rows separately.

---

# 22. Using temporary

`Using temporary` means MySQL needs to use a temporary table for part of the query processing.

This can occur with some queries involving:

- `GROUP BY`
- `DISTINCT`
- `UNION`
- Other operations

It is not automatically an error, but it can be important when optimizing expensive queries.

---

# 23. Using filesort

`Using filesort` means MySQL needs an additional sorting operation.

It may occur with some `ORDER BY` queries.

Despite its name, `filesort` does not necessarily mean that MySQL is literally writing a file to disk.

---

# 24. Using index condition

`Using index condition` indicates that MySQL is using **Index Condition Pushdown** to evaluate part of the condition while accessing the index.

This can reduce the number of full table rows that need to be examined.

---

# 25. Add an Index

Our query searches the `SALARY` column:

    SELECT NAME
    FROM EMP_INFO
    WHERE SALARY = 10000;

Currently, there is no index on `SALARY`.

We can create one:

    CREATE INDEX idx_salary
    ON EMP_INFO(SALARY);

Now `SALARY` has an index.

---

# 26. Check the Index

    SHOW INDEXES FROM EMP_INFO;

We should now see the index:

    idx_salary

on the `SALARY` column.

---

# 27. Run EXPLAIN Again

Run the same query:

    EXPLAIN
    SELECT NAME
    FROM EMP_INFO
    WHERE SALARY = 10000;

A sample result may look similar to:

    +----+-------------+----------+------+---------------+------------+---------+-------+------+-----------------------+
    | id | select_type | table    | type | possible_keys | key        | key_len | ref   | rows | Extra                 |
    +----+-------------+----------+------+---------------+------------+---------+-------+------+-----------------------+
    | 1  | SIMPLE      | EMP_INFO | ref  | idx_salary    | idx_salary | 5       | const | 2    | Using index condition |
    +----+-------------+----------+------+---------------+------------+---------+-------+------+-----------------------+

The exact output can vary because MySQL's optimizer makes decisions based on table statistics and other factors.

---

# 28. Compare Before and After Index

Before creating the index:

    type = ALL
    key  = NULL
    rows = 5

This indicates a full table scan in this example.

After creating the index:

    type = ref
    key  = idx_salary
    rows = 2

This indicates that MySQL can use the `idx_salary` index to find matching rows.

The main improvement is that MySQL can avoid scanning every row when the index is useful.

---

# 29. EXPLAIN with Primary Key

The `ID` column is already a primary key.

Run:

    EXPLAIN
    SELECT *
    FROM EMP_INFO
    WHERE ID = 1;

Because `ID` is a primary key, MySQL can use the primary key index to locate the record efficiently.

The `type` may show:

    const

and:

    key = PRIMARY

---

# 30. EXPLAIN with a Range Condition

Example:

    EXPLAIN
    SELECT *
    FROM EMP_INFO
    WHERE SALARY > 10000;

If the `SALARY` index is useful, the access type may be:

    range

This means MySQL can use a range of values from the index.

---

# 31. EXPLAIN with ORDER BY

Example:

    EXPLAIN
    SELECT *
    FROM EMP_INFO
    ORDER BY SALARY;

EXPLAIN can help us determine how MySQL handles the sorting operation.

The `Extra` column may provide information such as:

    Using filesort

---

# 32. EXPLAIN with Multiple Conditions

Example:

    EXPLAIN
    SELECT *
    FROM EMP_INFO
    WHERE SALARY > 10000
    AND DEPARTMENT = 'IT';

MySQL's optimizer decides which available indexes are useful.

If appropriate indexes exist, the execution plan may use one of them or a combination depending on the query and table statistics.

---

# 33. EXPLAIN and Query Optimization

EXPLAIN is useful when a query is slow.

A common approach is:

    1. Write the SQL query.
    2. Run EXPLAIN.
    3. Check the execution plan.
    4. Look at the indexes being considered.
    5. Check the index actually being used.
    6. Check the estimated rows.
    7. Check the Extra column.
    8. Consider whether an appropriate index is missing.
    9. Add or modify indexes when appropriate.
    10. Run EXPLAIN again and compare the plan.

---

# 34. Important EXPLAIN Columns

When learning EXPLAIN, focus first on these columns:

    type

Shows how MySQL accesses the table.

    possible_keys

Shows indexes that MySQL considers possible.

    key

Shows the index MySQL actually chooses.

    rows

Shows the estimated number of rows MySQL expects to examine.

    Extra

Provides additional information about the execution.
