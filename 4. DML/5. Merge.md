# MERGE-Like Operations in MySQL

MySQL does not have a `MERGE` statement like SQL Server or Oracle.

A `MERGE` operation generally means:

- If the record does not exist, insert it.
- If the record already exists, update it.

In MySQL, we can achieve this behavior using alternatives such as:

1. `INSERT ... ON DUPLICATE KEY UPDATE`
2. `REPLACE INTO`

---

# 1. MERGE Using INSERT ... ON DUPLICATE KEY UPDATE

`INSERT ... ON DUPLICATE KEY UPDATE` is a MySQL feature used to handle duplicate key conflicts.

If the `INSERT` statement tries to insert a value that already exists in a `PRIMARY KEY` or `UNIQUE` column, MySQL updates the existing record instead of generating a duplicate-key error.

---

## Step 1: Create Table

Create a table named `EMP_INFO_MERGE`.

The `ID` column is defined as the `PRIMARY KEY`.

    CREATE TABLE EMP_INFO_MERGE (
        ID INT PRIMARY KEY,
        FIRST_NAME VARCHAR(50),
        LAST_NAME VARCHAR(50),
        SALARY FLOAT
    );

---

## Step 2: Insert Initial Data

    INSERT INTO EMP_INFO_MERGE
    (ID, FIRST_NAME, LAST_NAME, SALARY)
    VALUES
    (1, 'Ram', 'Kumar', 25000),
    (2, 'Ravi', 'Sharma', 30000);

View the data:

    SELECT * FROM EMP_INFO_MERGE;

Output:

    +----+------------+-----------+--------+
    | ID | FIRST_NAME | LAST_NAME | SALARY |
    +----+------------+-----------+--------+
    |  1 | Ram        | Kumar     | 25000  |
    |  2 | Ravi       | Sharma    | 30000  |
    +----+------------+-----------+--------+

---

# 2. ON DUPLICATE KEY UPDATE

### Syntax

    INSERT INTO table_name (column1, column2, column3)
    VALUES (value1, value2, value3)
    ON DUPLICATE KEY UPDATE
        column_name = new_value;

When the inserted key already exists, the `ON DUPLICATE KEY UPDATE` part is executed.

---

## Case 1: Insert a New Record

Suppose we want to insert:

    ID = 3

ID `3` does not currently exist in the table.

    INSERT INTO EMP_INFO_MERGE
    (ID, FIRST_NAME, LAST_NAME, SALARY)
    VALUES
    (3, 'Raj', 'Verma', 28000)
    ON DUPLICATE KEY UPDATE
        SALARY = VALUES(SALARY);

Since ID `3` does not exist, MySQL inserts a new record.

View the data:

    SELECT * FROM EMP_INFO_MERGE;

---

## Case 2: Update an Existing Record

Suppose ID `1` already exists.

    INSERT INTO EMP_INFO_MERGE
    (ID, FIRST_NAME, LAST_NAME, SALARY)
    VALUES
    (1, 'Ram', 'Kumar', 27000)
    ON DUPLICATE KEY UPDATE
        SALARY = VALUES(SALARY);

ID `1` already exists.

Therefore, MySQL does not insert another record.

Instead, the existing record is updated:

    ID = 1
    SALARY = 27000

View the data:

    SELECT * FROM EMP_INFO_MERGE;

---

# 3. Understanding ON DUPLICATE KEY UPDATE

Consider:

    INSERT INTO EMP_INFO_MERGE
    (ID, FIRST_NAME, LAST_NAME, SALARY)
    VALUES
    (1, 'Ram', 'Kumar', 27000)
    ON DUPLICATE KEY UPDATE
        SALARY = VALUES(SALARY);

The process is:

    ID 1 exists?
          |
       YES
          |
    Update existing record
          |
    SALARY = 27000

If we use a new ID:

    INSERT INTO EMP_INFO_MERGE
    (ID, FIRST_NAME, LAST_NAME, SALARY)
    VALUES
    (10, 'Anu', 'Reddy', 35000)
    ON DUPLICATE KEY UPDATE
        SALARY = VALUES(SALARY);

The process is:

    ID 10 exists?
          |
        NO
          |
    Insert new record

---

# 4. Updating Multiple Columns

We can update multiple columns when a duplicate key is found.

### Example

    INSERT INTO EMP_INFO_MERGE
    (ID, FIRST_NAME, LAST_NAME, SALARY)
    VALUES
    (1, 'Rama', 'Kumar', 30000)
    ON DUPLICATE KEY UPDATE
        FIRST_NAME = VALUES(FIRST_NAME),
        LAST_NAME = VALUES(LAST_NAME),
        SALARY = VALUES(SALARY);

If ID `1` already exists, its `FIRST_NAME`, `LAST_NAME`, and `SALARY` values will be updated.

---

# 5. MERGE Using REPLACE INTO

Another MySQL alternative is `REPLACE INTO`.

`REPLACE INTO` works differently from `ON DUPLICATE KEY UPDATE`.

If a row with the same `PRIMARY KEY` or `UNIQUE` key already exists:

1. The existing row is deleted.
2. A new row is inserted.

### Syntax

    REPLACE INTO table_name
    (column1, column2, column3)
    VALUES
    (value1, value2, value3);

---

## Example

    REPLACE INTO EMP_INFO_MERGE
    (ID, FIRST_NAME, LAST_NAME, SALARY)
    VALUES
    (2, 'Ravi', 'Sharma', 35000);

ID `2` already exists.

`REPLACE INTO` removes the old row with ID `2` and inserts the new row.

The salary becomes `35000`.

View the data:

    SELECT * FROM EMP_INFO_MERGE;

---

# 6. ON DUPLICATE KEY UPDATE vs REPLACE INTO

These two approaches are not exactly the same.

### ON DUPLICATE KEY UPDATE

    INSERT INTO EMP_INFO_MERGE
    (ID, FIRST_NAME, LAST_NAME, SALARY)
    VALUES
    (2, 'Ravi', 'Sharma', 35000)
    ON DUPLICATE KEY UPDATE
        SALARY = VALUES(SALARY);

The existing row is updated.

### REPLACE INTO

    REPLACE INTO EMP_INFO_MERGE
    (ID, FIRST_NAME, LAST_NAME, SALARY)
    VALUES
    (2, 'Ravi', 'Sharma', 35000);

The existing row is deleted and a new row is inserted.

For most upsert-like situations, `INSERT ... ON DUPLICATE KEY UPDATE` is generally safer because it performs an update rather than deleting and reinserting the row.

---

# 7. Important Note About REPLACE INTO

`REPLACE INTO` should be used carefully.

Because MySQL handles a matching row by deleting it and inserting a new row, it can have consequences when the table has:

- Foreign key relationships
- Triggers
- `AUTO_INCREMENT`
- Other dependencies on the existing row

Therefore, when the intention is simply to update an existing record, `INSERT ... ON DUPLICATE KEY UPDATE` is often a better choice.

# CONCAT and CONCAT_WS in MySQL

`CONCAT()` and `CONCAT_WS()` are string functions used to combine multiple values into a single string.

`CONCAT` means **concatenate**.

`CONCAT_WS` means **concatenate with separator**.

---

# 8. Create Table for CONCAT Example

    CREATE TABLE EMP_INFO_MERGE (
        ID INT PRIMARY KEY,
        FIRST_NAME VARCHAR(50),
        LAST_NAME VARCHAR(50),
        SALARY FLOAT
    );

---

# 9. Insert Sample Data

    INSERT INTO EMP_INFO_MERGE
    (ID, FIRST_NAME, LAST_NAME, SALARY)
    VALUES
    (1, 'Ram', 'Kumar', 25000),
    (2, 'Ravi', 'Sharma', 30000),
    (3, 'Raj', NULL, 28000),
    (4, NULL, 'Verma', 31000),
    (5, NULL, NULL, 22000);

View the data:

    SELECT * FROM EMP_INFO_MERGE;

The table contains:

    | ID | FIRST_NAME | LAST_NAME | SALARY |
    |----|------------|-----------|--------|
    | 1  | Ram        | Kumar     | 25000  |
    | 2  | Ravi       | Sharma    | 30000  |
    | 3  | Raj        | NULL      | 28000  |
    | 4  | NULL       | Verma     | 31000  |
    | 5  | NULL       | NULL      | 22000  |

---

# 10. CONCAT Function

`CONCAT()` is used to combine two or more strings.

### Syntax

    CONCAT(value1, value2, value3, ...)

### Example

    SELECT CONCAT('Hello', ' ', 'World');

Output:

    Hello World

---

# 11. Combine First Name and Last Name Using CONCAT

    SELECT
        FIRST_NAME,
        LAST_NAME,
        CONCAT(FIRST_NAME, ' ', LAST_NAME) AS CONCAT_FULLNAME
    FROM EMP_INFO_MERGE;

Output:

    | FIRST_NAME | LAST_NAME | CONCAT_FULLNAME |
    |------------|-----------|-----------------|
    | Ram        | Kumar     | Ram Kumar       |
    | Ravi       | Sharma    | Ravi Sharma     |
    | Raj        | NULL      | NULL            |
    | NULL       | Verma     | NULL            |
    | NULL       | NULL      | NULL            |

---

## CONCAT and NULL

`CONCAT()` returns `NULL` if any of its arguments is `NULL`.

For example:

    CONCAT('Raj', ' ', NULL)

returns:

    NULL

Similarly:

    CONCAT(NULL, 'Verma')

returns:

    NULL

Therefore, `CONCAT()` is not NULL-safe when combining values that may contain `NULL`.

---

# 12. CONCAT_WS Function

`CONCAT_WS()` means:

**CONCAT With Separator**

It combines values using a specified separator.

### Syntax

    CONCAT_WS(separator, value1, value2, value3, ...)

### Example

    SELECT CONCAT_WS(' ', 'Ram', 'Kumar');

Output:

    Ram Kumar

Here:

    ' '

is the separator.

---

# 13. Combine Names Using CONCAT_WS

    SELECT
        FIRST_NAME,
        LAST_NAME,
        CONCAT_WS(' ', FIRST_NAME, LAST_NAME) AS WS_FULLNAME
    FROM EMP_INFO_MERGE;

Output:

    | FIRST_NAME | LAST_NAME | WS_FULLNAME |
    |------------|-----------|-------------|
    | Ram        | Kumar     | Ram Kumar   |
    | Ravi       | Sharma    | Ravi Sharma |
    | Raj        | NULL      | Raj         |
    | NULL       | Verma     | Verma       |
    | NULL       | NULL      |             |

---

# 14. CONCAT vs CONCAT_WS

## CONCAT

    CONCAT(FIRST_NAME, ' ', LAST_NAME)

If any argument is `NULL`, the result is generally `NULL`.

Example:

    CONCAT('Raj', ' ', NULL)

Result:

    NULL

---

## CONCAT_WS

    CONCAT_WS(' ', FIRST_NAME, LAST_NAME)

`CONCAT_WS()` skips `NULL` values.

Example:

    CONCAT_WS(' ', 'Raj', NULL)

Result:

    Raj

Another example:

    CONCAT_WS(' ', NULL, 'Verma')

Result:

    Verma

If all values are `NULL`, the result is an empty string.

---
