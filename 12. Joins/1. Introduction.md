# MySQL Joins

## What is a JOIN?

In MySQL, a **JOIN** is used to combine rows from two or more tables based on a related column.

Usually, tables are connected using:

* **Primary Key (PK)** — uniquely identifies a row in a table.
* **Foreign Key (FK)** — refers to a primary key in another table.

### Simple Example

If we have:

```text
employees
    |
    | dept_id
    ↓
departments
```

We can use `JOIN` to get employee names along with their department names.

---

# Why Do We Use JOINs?

### 1. Retrieve Data from Multiple Tables

JOINs allow us to get data from different tables in a single query.

### 2. Establish Relationships

JOINs connect related tables using common columns.

### 3. Efficient Data Querying

Instead of writing separate queries for different tables, we can combine the required information using JOINs.

### 4. Access Related Information

For example, we can retrieve:

```text
Employee Name + Department Name + Manager Name
```

using multiple JOINs.

---

# Types of JOINs in MySQL

| JOIN Type         | Description                                                           |
| ----------------- | --------------------------------------------------------------------- |
| `INNER JOIN`      | Returns only matching rows from both tables                           |
| `LEFT JOIN`       | Returns all rows from the left table and matching rows from the right |
| `RIGHT JOIN`      | Returns all rows from the right table and matching rows from the left |
| `FULL OUTER JOIN` | Returns all rows from both tables; MySQL does not support it directly |
| `CROSS JOIN`      | Returns every possible combination of rows                            |
| `SELF JOIN`       | Joins a table with itself                                             |

> **Note:** `JOIN` by itself usually means `INNER JOIN`.

---

# 1. INNER JOIN

`INNER JOIN` returns **only the rows that have a matching value in both tables**.

### Syntax

```sql
SELECT columns
FROM table1
INNER JOIN table2
    ON table1.column = table2.column;
```

`JOIN` can also be used instead of `INNER JOIN`:

```sql
SELECT columns
FROM table1
JOIN table2
    ON table1.column = table2.column;
```

### Easy Way to Remember

```text
INNER JOIN
Only matching records
```

---

# 2. LEFT JOIN

`LEFT JOIN` returns:

* All rows from the **left table**
* Matching rows from the **right table**
* `NULL` when there is no matching row in the right table

### Syntax

```sql
SELECT columns
FROM table1
LEFT JOIN table2
    ON table1.column = table2.column;
```

### Easy Way to Remember

```text
LEFT JOIN
All LEFT + matching RIGHT
```

---

# 3. RIGHT JOIN

`RIGHT JOIN` returns:

* All rows from the **right table**
* Matching rows from the **left table**
* `NULL` when there is no matching row in the left table

### Syntax

```sql
SELECT columns
FROM table1
RIGHT JOIN table2
    ON table1.column = table2.column;
```

### Easy Way to Remember

```text
RIGHT JOIN
All RIGHT + matching LEFT
```

---

# 4. FULL OUTER JOIN

`FULL OUTER JOIN` returns:

* All matching rows
* All unmatched rows from the left table
* All unmatched rows from the right table

### Important

**MySQL does not support `FULL OUTER JOIN` directly.**

A common workaround is to use `UNION` with `LEFT JOIN` and `RIGHT JOIN`.

```sql
SELECT *
FROM table1
LEFT JOIN table2
    ON table1.id = table2.id

UNION

SELECT *
FROM table1
RIGHT JOIN table2
    ON table1.id = table2.id;
```

### Easy Way to Remember

```text
FULL OUTER JOIN
Everything from LEFT + everything from RIGHT
```

---

# 5. CROSS JOIN

`CROSS JOIN` returns the **Cartesian product**.

Every row from the first table is combined with every row from the second table.

### Syntax

```sql
SELECT *
FROM table1
CROSS JOIN table2;
```

### Example

If:

```text
Table A → 3 rows
Table B → 4 rows
```

Then:

```text
3 × 4 = 12 rows
```

will be returned.

### Easy Way to Remember

```text
CROSS JOIN
Every row of A × Every row of B
```

---

# 6. SELF JOIN

A `SELF JOIN` means joining a table **with itself**.

It is useful when rows in the same table have a relationship with each other.

### Example Use Case

An employee table may contain:

```text
emp_id
emp_name
manager_id
```

Here, `manager_id` can refer to another employee in the same table.

We can use a SELF JOIN to find an employee and their manager.

### Example

```sql
SELECT 
    e.emp_name AS Employee,
    m.emp_name AS Manager
FROM employees e
LEFT JOIN employees m
    ON e.manager_id = m.emp_id;
```

Here:

```text
e → Employee
m → Manager
```

Both aliases refer to the same `employees` table.

---

# Quick JOIN Revision

```text
INNER JOIN
→ Only matching rows

LEFT JOIN
→ All rows from LEFT + matching RIGHT

RIGHT JOIN
→ All rows from RIGHT + matching LEFT

FULL OUTER JOIN
→ All rows from both tables
→ Not directly supported by MySQL

CROSS JOIN
→ Every combination of rows

SELF JOIN
→ Table joined with itself
```

# JOIN Examples

# 1. INNER JOIN — Employees + Departments

We want to display employee names along with their department names.

```sql
SELECT e.emp_name, d.dept_name
FROM employees e
JOIN departments d
    ON e.dept_id = d.dept_id;
```

### Result

```text
+--------------+-----------------+
| emp_name     | dept_name       |
+--------------+-----------------+
| John Doe     | Engineering     |
| Jane Smith   | Engineering     |
| Samuel Green | Human Resources |
| Nina Patel   | Marketing       |
| Luke Brown   | Finance         |
| Emily Davis  | Human Resources |
+--------------+-----------------+
```

`John Ram` is not returned because his `dept_id = 5` does not exist in the `departments` table.

---

# 2. LEFT JOIN — All Employees

We want **all employees**, even if their department does not exist.

```sql
SELECT e.emp_name, d.dept_name
FROM employees e
LEFT JOIN departments d
    ON e.dept_id = d.dept_id;
```

### Result

```text
+--------------+-----------------+
| emp_name     | dept_name       |
+--------------+-----------------+
| John Doe     | Engineering     |
| Jane Smith   | Engineering     |
| Samuel Green | Human Resources |
| Nina Patel   | Marketing       |
| Luke Brown   | Finance         |
| Emily Davis  | Human Resources |
| John Ram     | NULL            |
+--------------+-----------------+
```

`John Ram` is included because `LEFT JOIN` keeps **all rows from the employees table**.

Since there is no matching department, `dept_name` is `NULL`.

---

# 3. RIGHT JOIN — All Departments

We want **all departments**, even if there are no employees in them.

```sql
SELECT e.emp_name, d.dept_name
FROM employees e
RIGHT JOIN departments d
    ON e.dept_id = d.dept_id;
```

### Result

```text
+--------------+-----------------+
| emp_name     | dept_name       |
+--------------+-----------------+
| John Doe     | Engineering     |
| Jane Smith   | Engineering     |
| Samuel Green | Human Resources |
| Emily Davis  | Human Resources |
| Nina Patel   | Marketing       |
| Luke Brown   | Finance         |
| NULL         | Technician      |
+--------------+-----------------+
```

`Technician` is included even though no employee has `dept_id = 10`.

```sql

```

---

# Step 2: Add Manager Information

```sql
SELECT 
    e.emp_name,
    d.dept_name,
    m.manager_name
FROM employees e
LEFT JOIN departments d
    ON e.dept_id = d.dept_id
INNER JOIN managers m
    ON m.manager_id = e.manager_id;
```

### Result

```text
+--------------+-----------------+----------------+
| emp_name     | dept_name       | manager_name   |
+--------------+-----------------+----------------+
| John Doe     | Engineering     | Alice Johnson  |
| Jane Smith   | Engineering     | Alice Johnson  |
| Samuel Green | Human Resources | Bob Smith      |
| Nina Patel   | Marketing       | Catherine Lee  |
| Emily Davis  | Human Resources | Bob Smith      |
| John Ram     | NULL            | Alice Johnson  |
+--------------+-----------------+----------------+
```

Notice that `Luke Brown` is not returned because his `manager_id` is `NULL`, and we used an `INNER JOIN` for managers.

# Step 3: Add Project Information

Now we will add project information.

```sql
SELECT 
    e.emp_name,
    d.dept_name,
    m.manager_name,

    ON e.dept_id = d.dept_id
```

# Understanding Table Aliases

In the above queries, we use short names:

```sql
employees e
departments d
managers m
projects p
```

These are called **table aliases**.

Instead of writing:

```sql
employees.emp_name
```

we can write:

```sql
e.emp_name
```

### Common Aliases

```text
e → employees
d → departments
m → managers
p → projects
```

Aliases make JOIN queries shorter and easier to read.

---

# Important JOIN Syntax

The most important part of a JOIN is the `ON` condition.

Example:

```sql
JOIN departments d
    ON e.dept_id = d.dept_id;
```

This tells MySQL:

```text
Connect employees and departments
where their dept_id values are equal.
```

---

# Primary Key and Foreign Key Relationship

In our example:

```text
departments
-----------
dept_id ← Primary Key
```

and:

```text
employees
---------
dept_id ← Related/Foreign Key
```

The relationship is:

```text
employees.dept_id
        ↓
departments.dept_id
```

Similarly:

```text
employees.manager_id
        ↓
managers.manager_id
```

and:

```text
projects.team_member_id
        ↓
employees.emp_id
```

# Final JOIN Cheat Sheet

```text
INNER JOIN
→ Only matching records from both tables.

LEFT JOIN
→ All records from LEFT table
→ Matching records from RIGHT table
→ NULL when no match exists.

RIGHT JOIN
→ All records from RIGHT table
→ Matching records from LEFT table
→ NULL when no match exists.

FULL OUTER JOIN
→ All records from both tables
→ MySQL does not support it directly
→ Can be achieved using UNION.

CROSS JOIN
→ Every row from table A combined with every row from table B.

SELF JOIN
→ A table joined with itself.
```

## Key Point

**JOINs allow us to combine related data from multiple tables in a single SQL query.**

The most commonly used JOINs are:

```text
INNER JOIN → Matching records
LEFT JOIN  → Everything from left + matching right
RIGHT JOIN → Everything from right + matching left
```
