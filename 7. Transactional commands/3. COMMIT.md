# COMMIT and AUTO COMMIT in MySQL

## COMMIT

This command is used to permanently save the changes made during the current transaction.

Once a transaction is committed, its changes are made permanent and cannot be rolled back.

If we do not need to rollback and want to permanently save the changes, use:

```sql
COMMIT;
```

## Practical Example

### 1. Create Database

```sql
CREATE DATABASE IF NOT EXISTS CompanyDB;
USE CompanyDB;
```

### 2. Create Table

```sql
CREATE TABLE EMP_INFO (
    ID INT PRIMARY KEY,
    NAME VARCHAR(50),
    SALARY DECIMAL(10,2)
) ENGINE=InnoDB;
```

### 3. Insert Sample Data

```sql
INSERT INTO EMP_INFO VALUES
(1, 'Ram', 30000),
(2, 'Ravi', 40000);
```

### 4. Start Transaction

```sql
START TRANSACTION;
```

### 5. Update Data

```sql
UPDATE EMP_INFO
SET SALARY = SALARY + 5000
WHERE ID = 1;
```

### 6. Check the Data

```sql
SELECT * FROM EMP_INFO;
```

### 7. Commit the Transaction

```sql
COMMIT;
```

The salary change is now permanently saved.

### 8. Check the Data Again

```sql
SELECT * FROM EMP_INFO;
```

The updated salary remains saved.

> **Important:** After `COMMIT`, `ROLLBACK` cannot be used to undo the committed transaction.

---

# COMMIT vs ROLLBACK

```text
COMMIT
    ↓
Permanently saves transaction changes.

ROLLBACK
    ↓
Undoes uncommitted transaction changes.
```

## Practical Example

### Using COMMIT

```sql
START TRANSACTION;

UPDATE EMP_INFO
SET SALARY = SALARY + 1000
WHERE ID = 1;

COMMIT;
```

The salary increase is permanently saved.

### Using ROLLBACK

```sql
START TRANSACTION;

UPDATE EMP_INFO
SET SALARY = SALARY + 1000
WHERE ID = 1;

ROLLBACK;
```

The salary increase is undone.

# AUTO COMMIT MODE

By default, MySQL operates with `autocommit` enabled.

When `autocommit` is enabled, each successful statement that changes transactional data is automatically committed.

Therefore, if we want multiple statements to execute as one transaction, we can explicitly start a transaction:

```sql
START TRANSACTION;
```

or:

```sql
BEGIN;
```

## Check Auto Commit Status

```sql
SELECT @@autocommit;
```

Output:

```text
@@autocommit
1
```

- `1` → Auto commit is enabled.
- `0` → Auto commit is disabled.

---

# Disable Auto Commit Mode

To disable auto commit:

```sql
SET autocommit = 0;
```

or:

```sql
SET autocommit = OFF;
```

After disabling auto commit, changes to transactional tables are not automatically committed after every statement.

You must explicitly use:

```sql
COMMIT;
```

to save the changes, or:

```sql
ROLLBACK;
```

to undo them.

## Practical Example

```sql
SET autocommit = 0;

UPDATE EMP_INFO
SET SALARY = SALARY + 2000
WHERE ID = 1;

UPDATE EMP_INFO
SET SALARY = SALARY + 3000
WHERE ID = 2;

COMMIT;
```

Both updates are committed when `COMMIT` is executed.

## Practical Example Using ROLLBACK

```sql
SET autocommit = 0;

UPDATE EMP_INFO
SET SALARY = SALARY + 2000
WHERE ID = 1;

UPDATE EMP_INFO
SET SALARY = SALARY + 3000
WHERE ID = 2;

ROLLBACK;
```

Both uncommitted changes are rolled back.

---

# Enable Auto Commit Mode

To enable auto commit:

```sql
SET autocommit = 1;
```

or:

```sql
SET autocommit = ON;
```

## Practical Example

```sql
SET autocommit = 1;

UPDATE EMP_INFO
SET SALARY = SALARY + 1000
WHERE ID = 1;
```

The successful update is automatically committed.

---

# AUTO COMMIT and Explicit Transactions

Even when auto commit is enabled, we can explicitly start a transaction.

```sql
START TRANSACTION;

UPDATE EMP_INFO
SET SALARY = SALARY + 5000
WHERE ID = 1;

UPDATE EMP_INFO
SET SALARY = SALARY + 5000
WHERE ID = 2;

COMMIT;
```

Both updates are treated as one transaction and are permanently saved when `COMMIT` is executed.

If something goes wrong before `COMMIT`, use:

```sql
ROLLBACK;
```

## Practical Example

```sql
START TRANSACTION;

UPDATE EMP_INFO
SET SALARY = SALARY + 5000
WHERE ID = 1;

UPDATE EMP_INFO
SET SALARY = SALARY + 5000
WHERE ID = 2;

ROLLBACK;
```

Both updates are undone.

# DDL Commands and Auto Commit

DDL commands include:

```text
CREATE
ALTER
DROP
TRUNCATE
```

MySQL gives DDL statements special transaction behavior. Many DDL statements cause an implicit commit.

Therefore:

> **Important:** We cannot make all DDL commands rollbackable simply by disabling auto commit.

For example:

```sql
SET autocommit = 0;

START TRANSACTION;

UPDATE EMP_INFO
SET SALARY = SALARY + 1000
WHERE ID = 1;

CREATE TABLE TEST_TABLE (
    ID INT
);
```

The DDL statement can cause an implicit commit.

Therefore, do not assume that the previous `UPDATE` can still be rolled back after executing such DDL.

---

# DML vs DDL

## DML Statements

Common DML statements are:

```text
INSERT
UPDATE
DELETE
```

DML statements can participate in transactions when using a transactional storage engine such as InnoDB.

### Practical Example

```sql
START TRANSACTION;

UPDATE EMP_INFO
SET SALARY = SALARY + 1000
WHERE ID = 1;

ROLLBACK;
```

The update can be rolled back.

## DDL Statements

Common DDL statements are:

```text
CREATE
ALTER
DROP
TRUNCATE
```

DDL statements have special implicit-commit behavior in MySQL.

### Practical Example

```sql
START TRANSACTION;

CREATE TABLE TEST_TABLE (
    ID INT
);

ROLLBACK;
```

Do not assume that the `CREATE TABLE` operation can be undone by `ROLLBACK`.
