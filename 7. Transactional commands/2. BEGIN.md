# Transaction Control in MySQL

## START TRANSACTION

The `START TRANSACTION` command marks the beginning of a transaction.

All subsequent SQL statements executed in the same session are considered part of the transaction until the transaction is either committed or rolled back.

> **Important:** A transaction must be started before using `ROLLBACK` to undo the DML changes made within that transaction.

- **COMMIT** → Saves the transaction changes permanently.
- **ROLLBACK** → Reverts the changes made in the current transaction.

## What is a Transaction?

A transaction is a group of SQL statements that are executed as a single logical unit.

The purpose of a transaction is to ensure that related operations are completed consistently. For example, in a bank transfer, money should be deducted from one account and added to another account as one unit of work.

## Starting a Transaction

In MySQL, you can use:

```sql
START TRANSACTION;
```

or:

```sql
BEGIN;
```

These statements start a transaction. The transaction continues until `COMMIT`, `ROLLBACK`, or another transaction-ending operation occurs.

> **Note:** `BEGIN TRANSACTION;` is commonly associated with other database systems. For MySQL, use `START TRANSACTION;` or `BEGIN;`.

---

# COMMIT

`COMMIT` permanently saves all changes made during the current transaction.

## Syntax

```sql
COMMIT;
```

After `COMMIT`, the changes cannot be undone using `ROLLBACK`.

---

# ROLLBACK

`ROLLBACK` cancels the changes made during the current transaction since it began.

## Syntax

```sql
ROLLBACK;
```

It is useful when an error occurs or when you decide that the transaction should not be saved.

---

# Checking Transaction Status in MySQL

MySQL does **not** use `@@TRANCOUNT`.

`@@TRANCOUNT` is a SQL Server-specific variable.

To view transaction-related session counters in MySQL, you can use:

```sql
SHOW SESSION STATUS LIKE 'Com_commit';
SHOW SESSION STATUS LIKE 'Com_rollback';
```

- `Com_commit` → Number of `COMMIT` statements executed in the session.
- `Com_rollback` → Number of `ROLLBACK` statements executed in the session.

# Practical Example: Bank Fund Transfer

## Step 1: Create Database

```sql
CREATE DATABASE IF NOT EXISTS BankDB;
USE BankDB;
```

## Step 2: Create Table

```sql
CREATE TABLE BANK_ACCOUNTS (
    ACC_ID INT PRIMARY KEY,
    NAME VARCHAR(50),
    BALANCE DECIMAL(10,2)
) ENGINE=InnoDB;
```

## Step 3: Insert Sample Data

```sql
INSERT INTO BANK_ACCOUNTS (ACC_ID, NAME, BALANCE) VALUES
(1, 'Alice', 5000.00),
(2, 'Bob', 3000.00);
```

## Step 4: Check Initial Balances

```sql
SELECT * FROM BANK_ACCOUNTS;
```

Expected data:

```text
ACC_ID    NAME     BALANCE
1         Alice    5000.00
2         Bob      3000.00
```

---

# Example 1: Successful Transfer Using COMMIT

Suppose Alice sends ₹1000 to Bob.

Both operations must succeed:

1. Deduct ₹1000 from Alice.
2. Add ₹1000 to Bob.
3. Commit the transaction.

```sql
START TRANSACTION;

UPDATE BANK_ACCOUNTS
SET BALANCE = BALANCE - 1000
WHERE ACC_ID = 1;

UPDATE BANK_ACCOUNTS
SET BALANCE = BALANCE + 1000
WHERE ACC_ID = 2;

COMMIT;
```

## Check the Result

```sql
SELECT * FROM BANK_ACCOUNTS;
```

Expected result:

```text
ACC_ID    NAME     BALANCE
1         Alice    4000.00
2         Bob      4000.00
```

The changes are now permanently saved.

---

# Example 2: Rollback a Transaction

Suppose Alice sends ₹1000 to Bob, but we make a mistake while updating Bob's account.

```sql
START TRANSACTION;

UPDATE BANK_ACCOUNTS
SET BALANCE = BALANCE - 1000
WHERE ACC_ID = 1;

UPDATE BANK_ACCOUNTS
SET BALANCE = BALANCE + 1000
WHERE ACC_ID = 999;

ROLLBACK;
```

The second statement affects no row because account `999` does not exist.

`ROLLBACK` cancels the transaction changes, so Alice's debit is also undone.

## Check the Result

```sql
SELECT * FROM BANK_ACCOUNTS;
```

The balances return to their values before the transaction started.

---

# Example 3: Rollback Before Commit

```sql
START TRANSACTION;

UPDATE BANK_ACCOUNTS
SET BALANCE = BALANCE - 500
WHERE ACC_ID = 1;

SELECT * FROM BANK_ACCOUNTS;

ROLLBACK;

SELECT * FROM BANK_ACCOUNTS;
```

The first `SELECT` shows the temporary change within the transaction.

After `ROLLBACK`, the balance returns to its previous value.

---

# Example 4: Commit After Multiple Updates

```sql
START TRANSACTION;

UPDATE BANK_ACCOUNTS
SET BALANCE = BALANCE - 500
WHERE ACC_ID = 1;

UPDATE BANK_ACCOUNTS
SET BALANCE = BALANCE + 500
WHERE ACC_ID = 2;

COMMIT;
```

Both updates are permanently saved together.

---

# Example 5: Check Commit and Rollback Counters

```sql
SHOW SESSION STATUS LIKE 'Com_commit';

SHOW SESSION STATUS LIKE 'Com_rollback';
```

These commands show the commit and rollback counters for the current MySQL session.

# Important Points

1. `START TRANSACTION;` starts a transaction in MySQL.
2. `BEGIN;` can also be used to start a transaction.
3. `COMMIT;` permanently saves the changes made in the transaction.
4. `ROLLBACK;` undoes the transaction's changes since it began.
5. `ROLLBACK` is mainly used with transactional storage engines such as **InnoDB**.
6. A transaction ends when `COMMIT` or `ROLLBACK` is executed.
7. MySQL automatically commits transactions in several situations, including certain DDL statements such as `CREATE TABLE` and `ALTER TABLE`.
8. `@@TRANCOUNT` is a SQL Server feature and should not be used as a MySQL transaction counter.
9. `Com_commit` and `Com_rollback` are MySQL session status counters.
10. For a bank transfer, related debit and credit operations should be placed inside the same transaction.
11. Always verify the result before committing when performing critical updates.
12. Use `ROLLBACK` when an error or incorrect result is detected before committing.
13. The examples above use `ENGINE=InnoDB` because InnoDB supports transactions, row-level locking, and rollback.
