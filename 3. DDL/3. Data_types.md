# MySQL Data Types

A **data type** specifies what type of value can be stored in a column.

For example:

* Student name → Text
* Student age → Integer
* Student percentage → Decimal
* Student date of birth → Date

### Example

```sql
CREATE TABLE student (
    Roll INT,
    Name VARCHAR(30),
    Mark INT,
    Percentage DECIMAL(5,2),
    DOB DATE
);
```

In the above example:

* `Roll` uses `INT` because it stores integer values.
* `Name` uses `VARCHAR(30)` because it stores text.
* `Mark` uses `INT` because it stores whole numbers.
* `Percentage` uses `DECIMAL(5,2)` because it stores decimal values.
* `DOB` uses `DATE` because it stores a date.

---

# Categories of MySQL Data Types

MySQL data types are generally classified into three main categories:

1. **String Data Types**
2. **Numeric Data Types**
3. **Date and Time Data Types**

---

# 1. String Data Types

String data types are used to store:

* Text
* Characters
* Binary data

> **Note:** MySQL does not have a data type called `STRING`. Instead, MySQL provides different data types such as `CHAR`, `VARCHAR`, `TEXT`, `BINARY`, `BLOB`, `ENUM`, and `SET`.

## Common String Data Types

| Data Type | Description                                |
| --------- | ------------------------------------------ |
| `CHAR`    | Fixed-length character string              |
| `VARCHAR` | Variable-length character string           |
| `TEXT`    | Large text values                          |
| `BINARY`  | Fixed-length binary string                 |
| `BLOB`    | Binary Large Object                        |
| `ENUM`    | One value from a predefined list           |
| `SET`     | Zero or more values from a predefined list |

---

## CHAR

`CHAR` stands for **Character**.

It is used to store **fixed-length character strings**.

### Features of CHAR

* Stores character data.
* Can contain alphabets, numbers, and symbols.
* Maximum length is **255 characters**.
* Default size is `1`.
* Suitable when the values have a fixed or nearly fixed length.

### Syntax

```sql
column_name CHAR(size);
```

### Example

```sql
Gender CHAR(1);
```

Possible values:

```text
M
F
```

Another example:

```sql
CountryCode CHAR(2);
```

Possible values:

```text
IN
US
UK
```

### When to Use CHAR?

Use `CHAR` when the length of the data is fixed.

Examples:

* Gender code
* Country code
* State code
* Fixed-length identification codes

---

## VARCHAR

`VARCHAR` stands for **Variable Character**.

It is used to store **variable-length character strings**.

### Features of VARCHAR

* Stores variable-length text.
* The size must be specified.
* Maximum length can be up to `65,535` bytes, depending on the row size and character set.
* Uses storage based on the actual value length plus length information.
* Suitable for names, addresses, email addresses, etc.

### Syntax

```sql
column_name VARCHAR(size);
```

### Example

```sql
Name VARCHAR(30);
```

Possible values:

```text
Ravi
Suresh
Anil Kumar
```

### Example Table

```sql
CREATE TABLE student (
    Name VARCHAR(30)
);
```

### CHAR vs VARCHAR

| CHAR                             | VARCHAR                                              |
| -------------------------------- | ---------------------------------------------------- |
| Fixed-length string              | Variable-length string                               |
| Maximum length is 255 characters | Maximum length depends on row size and character set |
| Suitable for fixed-length values | Suitable for variable-length values                  |
| Fixed-length semantics           | Variable-length storage                              |

### Simple Example

Suppose we have:

```text
CHAR(10)
VARCHAR(10)
```

If we store:

```text
Ravi
```

`CHAR` uses fixed-length semantics, while `VARCHAR` uses variable-length storage.

---

## TEXT

`TEXT` is used to store **large amounts of text**.

It is useful when the amount of text is larger than what is normally stored in a `VARCHAR` column.

### Features of TEXT

* Used for long text values.
* Standard `TEXT` can store up to **65,535 bytes**.
* Useful for descriptions, comments, articles, and other long text.

### Example

```sql
Description TEXT;
```

### Example Table

```sql
CREATE TABLE product (
    ProductName VARCHAR(50),
    Description TEXT
);
```

Here:

* `ProductName` stores the product name.
* `Description` stores a longer description.

---

## BINARY

`BINARY` is used to store **fixed-length binary data**.

Binary data means data represented in the form of bytes rather than normal text characters.

### Features of BINARY

* Similar to `CHAR`, but stores binary strings.
* It has a fixed length.
* Maximum length is **255 bytes**.
* Values are treated as binary data.

### Syntax

```sql
column_name BINARY(size);
```

### Example

```sql
Code BINARY(10);
```

> **Note:** `BINARY` is different from `BLOB`. `BINARY` is generally used for smaller fixed-length binary values, while `BLOB` is designed for binary large objects.

---

## BLOB

`BLOB` stands for **Binary Large Object**.

It is used to store **binary data**.

Examples:

* Images
* Audio
* Files
* Documents
* Other binary information

### Features of BLOB

* Used for binary large objects.
* Standard `BLOB` can store up to **65,535 bytes**.
* Stores binary data rather than normal text.

### Example

```sql
ImageData BLOB;
```

### Example Table

```sql
CREATE TABLE student_photo (
    Roll INT,
    Photo BLOB
);
```

Here:

* `Roll` stores the student's roll number.
* `Photo` can store binary image data.

### BINARY vs BLOB

| BINARY                                        | BLOB                                       |
| --------------------------------------------- | ------------------------------------------ |
| Fixed-length binary string                    | Binary large object                        |
| Maximum 255 bytes                             | Standard BLOB can store up to 65,535 bytes |
| Suitable for smaller fixed-size binary values | Suitable for larger binary data            |

---

## ENUM

`ENUM` is used when a column should contain **one value from a predefined list of values**.

### Features of ENUM

* Allows only one value from the defined list.
* Useful when the possible values are known in advance.
* Helps restrict the values that can be stored.

### Syntax

```sql
column_name ENUM('value1', 'value2', 'value3');
```

### Example

```sql
Gender ENUM('Male', 'Female');
```

The column can contain:

```text
Male
```

or:

```text
Female
```

### Another Example

```sql
Status ENUM('Active', 'Inactive');
```

Possible values:

```text
Active
Inactive
```

### When to Use ENUM?

Use `ENUM` when a column has a small and fixed list of possible values.

Examples:

* Gender
* Status
* Order status
* Yes/No type choices

---

## SET

`SET` is used to store **zero or more values from a predefined list**.

This is different from `ENUM`.

### ENUM

Stores **one value** from a predefined list.

### SET

Can store **multiple values** from a predefined list.

### Syntax

```sql
column_name SET('value1', 'value2', 'value3');
```

### Example

```sql
Hobbies SET('Reading', 'Music', 'Travel');
```

Possible values include:

```text
Reading
```

```text
Reading, Music
```

```text
Music, Travel
```

```text
Reading, Music, Travel
```

### ENUM vs SET

| ENUM                             | SET                                        |
| -------------------------------- | ------------------------------------------ |
| Stores one value                 | Stores zero or more values                 |
| One value from the list          | Multiple values from the list              |
| Example: `ENUM('Male','Female')` | Example: `SET('Reading','Music','Travel')` |

---

# 2. Numeric Data Types

Numeric data types are used to store **numbers**.

They are mainly used to store:

* Whole numbers
* Decimal numbers
* Very large numbers
* Bit values

Examples:

```text
10
100
-50
85.5
12345.67
```

Common numeric data types are:

* `TINYINT`
* `SMALLINT`
* `MEDIUMINT`
* `INT`
* `BIGINT`
* `DECIMAL`
* `FLOAT`
* `DOUBLE`
* `BIT`

---

# SIGNED and UNSIGNED

Integer data types can be specified as either:

1. `SIGNED`
2. `UNSIGNED`

## SIGNED

A `SIGNED` integer can store:

* Positive values
* Negative values
* Zero

Example:

```sql
Age INT SIGNED;
```

## UNSIGNED

An `UNSIGNED` integer can store:

* Zero
* Positive values

It cannot store negative values.

Example:

```sql
Age INT UNSIGNED;
```

### Example

For `TINYINT`:

#### SIGNED

```text
-128 to 127
```

#### UNSIGNED

```text
0 to 255
```

> **Note:** Integer types are `SIGNED` by default unless `UNSIGNED` is specified.

---

The commonly used integer data types are:

* `TINYINT`
* `SMALLINT`

# FLOAT

`FLOAT` is used to store **approximate decimal numbers**.

It is useful when a value can contain decimal digits and approximate precision is acceptable.

### Example

```sql
Percentage FLOAT;
```

Possible value:

```text
85.75
```

### FLOAT with Precision

`FLOAT(p)` can specify approximate precision.

Older/common syntax also uses:

```sql
FLOAT(M,D)
```

where:

* `M` = Total number of digits
* `D` = Number of digits after the decimal point

For exact decimal values, `DECIMAL` is generally preferred.

---

# DOUBLE

`DOUBLE` is also used to store **approximate decimal numbers**.

It generally provides more precision than `FLOAT`.

### Example

```sql
Distance DOUBLE;
```

Possible value:

```text
12345.6789
```

### FLOAT vs DOUBLE

| FLOAT                                      | DOUBLE                                   |
| ------------------------------------------ | ---------------------------------------- |
| Approximate numeric value                  | Approximate numeric value                |
| Uses less storage                          | Uses more storage                        |
| Lower precision                            | Higher precision                         |
| Suitable when less precision is sufficient | Suitable when more precision is required |

---

# DECIMAL

`DECIMAL` is used to store **exact decimal values**.

It is commonly used for values where accuracy is important.

Examples:

* Salary
* Price
* Amount
* Percentage
* Financial values

## Syntax

```sql
column_name DECIMAL(precision, scale);
```

### Precision

**Precision** means the total number of digits.

### Scale

**Scale** means the number of digits after the decimal point.

### Example

```sql
Salary DECIMAL(7,2);
```

Here:

* `7` = Total number of digits
* `2` = Number of digits after the decimal point

A value such as:

```text
12345.67
```

has:

* 7 total digits
* 2 digits after the decimal point

### Important

For money and other exact decimal values, `DECIMAL` is generally preferred over `FLOAT` and `DOUBLE`.

---

# BIT

`BIT` is used to store **bit values**.

A bit can represent binary values such as:

```text
0
1
```

MySQL allows binary notation using `b''`.

### Example

```sql
BIT(4)
```

A value can be written as:

```sql
b'1111'
```

The binary value:

```text
1111
```

represents the decimal value:

```text
15
```

Another example:

```sql
b'11101'
```

The binary value:

```text
11101
```

represents the decimal value:

```text
29
```

# 3. Date and Time Data Types

Date and time data types are used to store:

* Dates
* Times
* Date and time values
* Years

The main date and time data types are:

* `DATE`
* `TIME`
* `DATETIME`
* `TIMESTAMP`
* `YEAR`

---

# DATE

`DATE` is used to store a **date**.

## Format

```text
YYYY-MM-DD
```

Where:

* `YYYY` = Year
* `MM` = Month
* `DD` = Day

### Example

```sql
DOB DATE;
```

Example value:

```text
2005-08-15
```

### Range

```text
1000-01-01 to 9999-12-31
```

### Example Table

```sql
CREATE TABLE student (
    Name VARCHAR(30),
    DOB DATE
);
```

---

# TIME

`TIME` is used to store **time values**.

## Format

```text
HH:MM:SS
```

Where:

* `HH` = Hours
* `MM` = Minutes
* `SS` = Seconds

### Example

```sql
StartTime TIME;
```

Example value:

```text
10:30:45
```

### Range

```text
-838:59:59 to 838:59:59
```

> **Note:** `TIME` can represent both normal time-of-day values and time intervals. Therefore, its range is greater than 24 hours.

---

# DATETIME

`DATETIME` is used to store both **date and time**.

## Format

```text
YYYY-MM-DD HH:MM:SS
```

### Example

```sql
CreatedAt DATETIME;
```

Example value:

```text
2026-08-10 10:30:45
```

### Range

```text
1000-01-01 00:00:00
to
9999-12-31 23:59:59
```

### Example

```sql
CREATE TABLE employee (
    Name VARCHAR(30),
    JoiningDate DATETIME
);
```

---

# TIMESTAMP

`TIMESTAMP` is used to store **date and time values**.

It is commonly used for recording events such as:

* Record creation time
* Record update time
* Login time
* Transaction time

## Format

```text
YYYY-MM-DD HH:MM:SS
```

### Example

```sql
CreatedAt TIMESTAMP;
```

Example value:

```text
2026-08-10 10:30:45
```

### Important Difference

`TIMESTAMP` has different behavior from `DATETIME`.

One important difference is that `TIMESTAMP` values are handled with time-zone conversion, while `DATETIME` values are not converted in the same way.

`TIMESTAMP` is also commonly used with automatic date/time features.

### Example

```sql
CreatedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP;
```

This can automatically store the current timestamp when a row is created.

---

# YEAR

`YEAR` is used to store a **year value**.

## Format

```text
YYYY
```

### Example

```sql
BirthYear YEAR;
```

Example value:

```text
2005
```

Another example:

```sql
GraduationYear YEAR;
```

Example value:

```text
2026
```

### Range

```text
1901 to 2155
```

---

# DATE vs TIME vs DATETIME vs TIMESTAMP vs YEAR

| Data Type   | Used For                              | Example               |
| ----------- | ------------------------------------- | --------------------- |
| `DATE`      | Date only                             | `2026-08-10`          |
| `TIME`      | Time only                             | `10:30:45`            |
| `DATETIME`  | Date and time                         | `2026-08-10 10:30:45` |
| `TIMESTAMP` | Date and time with timestamp behavior | `2026-08-10 10:30:45` |
| `YEAR`      | Year only                             | `2026`                |

---

# Practical Example Using Different Data Types

```sql
CREATE TABLE student (
    Roll INT,
    Name VARCHAR(30),
    Gender ENUM('Male', 'Female'),
    Hobbies SET('Reading', 'Music', 'Travel'),
    Mark INT,
    Percentage DECIMAL(5,2),
    DOB DATE,
    LoginTime TIME,
    CreatedAt DATETIME,
    BirthYear YEAR
);
```

### Explanation

| Column       | Data Type      | Purpose                               |
| ------------ | -------------- | ------------------------------------- |
| `Roll`       | `INT`          | Stores roll number                    |
| `Name`       | `VARCHAR(30)`  | Stores student name                   |
| `Gender`     | `ENUM`         | Stores one predefined gender value    |
| `Hobbies`    | `SET`          | Stores one or more predefined hobbies |
| `Mark`       | `INT`          | Stores marks                          |
| `Percentage` | `DECIMAL(5,2)` | Stores exact decimal percentage       |
| `DOB`        | `DATE`         | Stores date of birth                  |
| `LoginTime`  | `TIME`         | Stores login time                     |
| `CreatedAt`  | `DATETIME`     | Stores date and time                  |
| `BirthYear`  | `YEAR`         | Stores birth year                     |
